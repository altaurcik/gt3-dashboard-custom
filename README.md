# GT3 Dashboard Custom

Отдельный локальный GT3-дашборд в стиле F1 Dashboard Custom, с акцентом на Verstappen Racing №3.

## Запуск

Нужен Node.js 22 или новее. Установка npm-пакетов не требуется.

```powershell
cd gt3-dashboard-custom
npm start
```

Открыть [дашборд](http://localhost:3001/dashboard).
Также можно дважды щёлкнуть `start-dashboard.cmd`: он запускает сервер и открывает браузер.
Если порт занят: `$env:PORT=3002; npm start`. По умолчанию сервер доступен только локально.

## Возможности

- Реальный бесплатный Swiss Timing / SRO JSON: участники текущей гонки, классы, составы,
  позиции, разрывы, интервалы, времена и сектора при наличии у источника.
- Push-уведомления новых ревизий и мгновенная доставка снимков браузеру через SSE.
  HTTP-опрос раз в 5 с остаётся резервом. Частота обновления отдельной машины ограничена источником.
- `Current race` следует за текущей гонкой уикенда (GT4, GT2, GT3, McLaren Trophy):
  название серии/сессии, время старта, продолжительность и состав берутся из расписания.
  `GT3 · Verstappen #3` закрепляет гонку Ферстаппена. До публикации её каналов — ожидание и обратный отсчёт.
  Результаты квалификации не загружаются и не показываются, включая старый дисковый кэш.
- Избранный №3, поиск, фильтр в заголовке столбца CLASS, выбор двух экипажей и сравнение.
- CLASS применяется ко всей странице: карта/PIT, состав сравнения, Field, пит-стопы,
  смены пилотов и сообщения о машинах. Общие сообщения по трассе остаются видимыми.
- В GT3-сравнении по умолчанию A = №3, B = экипаж непосредственно перед ним в общей гоночной
  классификации. Два явных списка позволяют вручную выбрать A/B уже до старта из официальной
  заявки SRO. Флажок `Auto: crew ahead of A` доступен во всех сериях и выбирает B перед выбранным A,
  учитывая CLASS. Смена A сохраняет авторежим, ручной выбор B отключает его. Для других серий списки
  используют их фактические гоночные заявки; выбор A/B и авторежим сохраняются отдельно по сериям.
- Сравнение по одинаковым номерам кругов: LAP / A / B / Δ A−B, выделение более быстрого
  времени и вывод, кто быстрее на круг. Matched avg использует одинаковые чистые круги обоих
  экипажей; Race best показывает лучшее официальное время гонки. Неизвестные круги не выдумываются.
- История наблюдаемых кругов, пит-стопов и смен пилотов; Race Control из источника.
- LAST/BEST, компактная полоса S1/S2/S3 с прогрессом от источника и PACE по последним
  3/5/10 чистым кругам. Число использованных кругов указано рядом со средним временем.
  Незаконченный LastLap не считается завершённым; пропущенное время восстанавливается только
  по разнице двух наблюдаемых суммарных времён при продвижении ровно на один круг.
- Географическая карта в стиле F1 Dashboard Custom: MapLibre, OpenFreeMap, приглушённая
  подложка и здания, 3D/2D, Global/Top-down, масштаб, поворот, наклон, освещение и разворот панели.
  Локальный 2D-контур остаётся доступен при ошибке внешней подложки.
- Компоновки Side by side / Stacked, компактные строки, светлая/тёмная тема, TV Sync 0–120 с, пауза.
- Обратный отсчёт по Москве. Гоночный таймер берётся из источника.

## Ограничения

Swiss Timing — внешний недокументированный публичный канал, доступность и формат могут измениться.
Сам виджет ограничен доменами организатора; проект использует доступный без авторизации JSON,
не подменяя Origin/Referer и не встраивая запрещённый виджет.
GPS, радио, возраст шин и погода трассы в проверенном канале отсутствуют.
Наличие GPS у организатора подтверждено документами этапа, но открытый поток координат
не найден. Карта показывает Estimated-позиции по завершённым секторам на калиброванном
контуре SRO/OSM; это не GPS. A/B выделены, точки выбирают экипаж сравнения. PIT вынесен
отдельно; пауза и TV Sync действуют и на карту, устаревшие данные останавливают движение.
Плавность карты — на частоте кадров браузера. Каждый полученный сектор воспроизводится
за его измеренное время, с общей задержкой примерно в сектор (+8 с доставки), указанной на карте.
Это убирает регулярные остановки у отсечек; при отсутствии следующего сектора остаётся buffering.
Результат поиска и метод надёжного timing-based позиционирования —
[docs/MAP_POSITION_RESEARCH.md](docs/MAP_POSITION_RESEARCH.md).
Отдельных минисекторов F1 в проверенном формате нет: используются три реальных сектора
и SectBasedPcntPos, без выдуманных промежуточных отсечек.
История кругов/пит-стопов накапливается после запуска сервера; раньше произошедшие события не восстановлены.
Темп строится только по наблюдаемым кругам без пит-лейна и с зелёным флагом; точной классификации
удалённых кругов и полных стинтов источник не предоставляет. TV Sync буферизуется с открытия страницы.
При потере источника последний снимок сохраняется с явной отметкой устаревания.

## Проверки

```powershell
npm run check
npm test
```

Проверка реального источника: [health](http://localhost:3001/api/health),
[полный снимок](http://localhost:3001/api/timing). Проверки `node:test` используют только
изолированные фикстуры и никогда не подмешивают их в приложение.

Архитектура — [PROJECT_MAP.md](PROJECT_MAP.md), источники — [DATA_SOURCES.md](DATA_SOURCES.md).
MapLibre GL JS 5.24.0 включён локально с BSD-лицензией; npm install для карты не нужен.
Географические тайлы OpenFreeMap требуют интернет-соединения и не требуют API-ключа.
