  Доступ проверен обычным GET, без аккаунта, cookies, подмены Origin/Referer или платного API.

  Проверены анонимные read-only join/leave `RAC_PROD|<CHANNEL>` и уведомления revision,

## Каналы

`SRO_SEASONS_JSON` → текущий сезон; `SRO_2026_SEASON_JSON` → этапы.
`SRO_2026_SCHEDULE_<MEETING-ID>_JSON` → сессии и чемпионаты.
`SRO_2026_TIMING_<UNIT-ID>_JSON` → `UntInfo` и `Results.MainResult`.
`SRO_2026_COMP_DETAIL_<UNIT-ID>_JSON` → экипажи, текущий пилот, pit, классы и сообщения.
Все имена каналов приводятся к uppercase, суффикс HTTP — `.json`.

В source snapshot есть собственные IDs выбранного этапа и соревнования.
Режим Current race использует гонки Type=0 всех серий этого уикенда (GT4, GT2, GT3,
McLaren Trophy), состояние State и PresentationRoundId. Режим GT3 закрепляет конкретный race ID.
Метаданные серии/старта/длительности и фильтр классов соответствуют выбранной гонке.
404 ещё не опубликованного race JSON означает пустой экран ожидания выбранной гонки.
Квалификация не используется ни как сетевой, ни как дисковый fallback.

| Поле | Источник / ограничение |
| --- | --- |
| Позиция, класс, разрывы, интервалы, best/laps | MainResult; отсутствующее остаётся null |
| LAST | Только завершённый LastLap.Time; при текущем незавершённом LastLap — разница TotalTime между двумя наблюдениями ровно в один круг; источник расчёта указан в tooltip |
| Текущий пилот | CurrentDriverId из выбранной race-сессии |
| Автоматический соперник A | Во всех сериях; в All — точный P−1 относительно выбранного A; при фильтре — предшественник внутри выбранного класса; только из показанного снимка, без фиксированной команды. В GT3 по умолчанию A = №3 |
| Сектора | LastLap.Intermediates S1/S2/S3; цвета TimeState 1/2 — personal/overall best |
| Прогресс секторов | SectBasedPcntPos в диапазоне 0–3, как в публичном клиенте Swiss Timing; не GPS |
| Позиции карты Estimated | Отложенное воспроизведение завершённых секторов S1/S2/S3 за их измеренное время на общих часах TotalTime/sectorLapNumber; буфер ≈ 95-й процентиль трёх последних секторов каждого экипажа + 8 с. Длины 1616,4/1360,8/1675,8 м, постоянная скорость внутри каждого сектора, без GPS. До готовности буфера виден полученный SectBasedPcntPos с подписью buffering. PIT/retired/unknown исключены; завершённая гонка / reduced motion неподвижны |
| Минисектора F1 | В проверенном формате отсутствуют; три сектора не делятся на вымышленные отсечки |
| Флаги и оставшееся время | UntInfo.TrackFlag, ChequeredFlag, RemainingTime |
| Race Control | COMP_DETAIL.Messages.Text / Time (WEST); в интерфейсе новые сверху по timestamp, независимо от порядка источника; до 100 наблюдавшихся сообщений на сессию |
| Цвет Race Control | Классификация текста SRO по семантике F1 EventPanels; Penalty важнее Track Limits, Investigation важнее упоминания FCY; неизвестное остаётся Info. Это тип исторического сообщения, не текущее состояние трассы |
| Число пит-стопов и IN PIT | PitStopCount / InPitLane |
| История питов и смен пилотов | Наблюдаемые переходы после подключения; время наблюдения, не точное время пересечения линии |
| Представление PIT | Общая запись только для одного номера и одинакового времени наблюдения; PIT IN/PIT OUT, круг и From→To раздельно. Историческое имя — из записанной предшествующей смены, неизвестное не заменяется текущим пилотом; точная длительность не вычисляется |
| Темп | Среднее последних 3/5/10 валидных наблюдаемых чистых кругов с явным числом samples; pit/caution исключаются, полная история и deleted-lap classification недоступны |
| Lap comparison | Реальные времена одного и того же номера круга; Δ=A−B в секундах. Matched avg — одинаковые чистые круги обоих экипажей в выбранном окне, с числом пар; неизвестные круги не восстанавливаются |
| GPS, радио, шины, погода трассы | В проверенном фиде отсутствуют; не генерируются |

Источник может исправлять результаты. Интерфейс всегда использует свежую полученную редакцию
JSON, а не зафиксированный первоначальный PDF. В интерфейсе представлены только данные выбранной гонки.
Фильтр класса применяется к общему снимку страницы: машины, карта, сравнение, пит-стопы,
смены пилотов и история ограничены классом. Race Control сохраняет общие команды по трассе
и сообщения, относящиеся хотя бы к одной машине класса; текст сообщения не переписывается.
Исходный поток не изменяется и не обрезается; All возвращает полный состав и события.

## Что проверено в разработке

17 октября 2026 получен реальный активный поток GT4 European Series · Race 1:
35 машин, меняющиеся uid/RemainingTime, флаги Safety Car → Green, времена S1–S3,
LAST/BEST и сообщения Race Control. GT3 остаётся State=0, каналы ещё не опубликованы.
Обнаружено CDN-кэширование JSON на 60 с: запросы включают параметры s (объявленный push uid,
либо последний полученный uid) и t (текущая секунда),
с Cache-Control: no-cache. Получение того же uid всё равно не считается изменением.
Переключение серий, изоляция кэша/истории и исчезновение источника проверены contract fixtures.

После жалобы на редкие обновления проверен push-канал: изменения тайминга анонсируются
примерно каждые 2,2 с. Сервер получает полный HTTPS JSON по уведомлению и сразу отправляет
его браузеру через SSE. Реальный замер 8 последовательных uid 424–431: интервалы доставки
1,7–2,7 с; от получения уведомления сервером до локального SSE-клиента 0,19–0,68 с.
Это частота снимков всего поля, а не обещание новой отсечки каждой машины каждые 2 с.
Числовые S1/S2/S3 меняются при пересечении отсечек; SectBasedPcntPos меняется с частотой,
которую публикует источник. Под жёлтым флагом прохождение секторов занимает больше времени.
Дополнительные F1-минисектора и GPS-телеметрия не добавлены. Расчётные точки Estimated
использовали полученный прогресс и короткий ограниченный прогноз на его основе. Замер отдельных машин дал интервалы изменения прогресса 0,9–9,4 с,
медиана 3,2 с: частота нового положения отличается от частоты снимков всего поля.

После жалобы на остановки у отсечек прогноз заменён отложенным воспроизведением
подтверждённых секторов. Сектор проходится за опубликованное время; машины используют
общую шкалу TotalTime, карта отстаёт от таблицы примерно на сектор с запасом доставки 8 с.
Задержка показана на карте. Буфер растёт без перемотки назад при более долгих секторах;
при нехватке данных показывается buffering. Ни время нового сектора, ни новый круг не генерируются.

На 18:20 MSK автоматический выбор переключился на предстоящую GT3 Race: State=0,
каналы уже опубликованы, 61 строка без времён секторов. Карта ожидает первые реальные отсечки;
живая плавность нового режима до старта не проверялась, переходы проверены контрактными тестами.

После старта GT3 обнаружен накопленный буфер около 230 с: долгие ранние сектора сохранялись
в максимуме истории. Буфер ограничен недавними секторами поля с отсечением одиночных выбросов;
избыточная задержка пересобирается, при ожидании истории точки остаются видимыми по source progress.
Живой фид GT3 также выдаёт интервалы ревизий около 30 с, поэтому 20-секундный порог карты
заменён на длительность буфера + 15 с (20–120 с). Это допускает воспроизведение уже известных
секторов между пакетами; не даёт права создавать неподтверждённое движение или новые круги.
