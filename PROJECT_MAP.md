# Карта GT3 Dashboard Custom

## Назначение

Самостоятельный локальный GT World Challenge dashboard, визуально связанный с соседним
F1 Dashboard Custom. Собственный Git-репозиторий, запуск и источник данных.
Исходный F1-проект не является runtime-зависимостью.

## Стек и маршруты

Node.js 22+ ESM, встроенный HTTP/fetch/node:test; клиент — HTML, CSS и ES modules.
Зависимости npm для установки отсутствуют; MapLibre GL JS 5.24.0 и его worker включены
локально в public/vendor/maplibre. Статические ассеты и шрифты лежат внутри проекта.

| Маршрут | Файл и назначение |
| --- | --- |
| `/`, `/dashboard` | [public/index.html](public/index.html) — основной экран |
| `/api/timing` | [server.mjs](server.mjs) → TimingProvider auto — текущая гонка; `?view=gt3` закрепляет GT3 |
| `/api/health` | То же состояние источника, сессии, число машин и время проверки |
| `/api/events?view=auto\|gt3` | SSE: нормализованные снимки сразу после получения сервером, heartbeat и переподключение |
| `/assets/*` | Локальная геометрия, шрифты и лицензии |

## Поток данных

```text
Swiss Timing public RAC_PROD / SRO JSON
  + Swiss Timing public WebSocket: уведомления revision
  -> src/provider.mjs: получение свежего HTTPS JSON по уведомлению; резервный poll
  -> src/normalize.mjs: экипажи + результаты + классы + сообщения
  -> ObservationHistory: только наблюдаемые круги, pit-in/out и смены пилотов
  -> /api/events (SSE), /api/timing (резерв)
  -> public/app.js: браузерный буфер TV Sync / пауза
  -> таблица, сравнение, Race Control и события
```

## Опрос, состояние и хранение

Push-уведомления Swiss Timing сообщают новые uid; через 80 мс объединения уведомлений
сервер получает полные HTTPS-документы и сразу передаёт снимок браузеру по SSE.
Сами pushData не применяются как патчи к результатам. Объявленная новая revision обходит TTL,
`s` запроса указывает объявленный uid. Случайно запоздавший HTTP-ответ браузера не заменяет более новый снимок.
Раз в 5 с остаётся резервный серверный опрос; клиент использует HTTP-опрос при недоступности SSE.
Общий серверный single-flight предотвращает удвоение запросов при нескольких вкладках.
Расписание кэшируется 15 с,
активные гоночные каналы 2.5 с; отсутствующие ещё не подготовленные каналы — 15 с.
Запросы имеют таймаут 12 с. WebSocket поддерживает ping/pong, watchdog и reconnect с backoff 1–30 с.
SSE отправляет heartbeat раз в 15 с; соединения медленных вкладок с буфером больше 1 МБ закрываются.
При pagehide EventSource закрывается; при остановке сервера закрываются WebSocket/SSE и таймеры.
Отсутствие race JSON до старта — нормальное состояние.
Пустая или несовпадающая по ID сессия не принимается.
Каналы квалификации не запрашиваются. До публикации обоих race JSON API возвращает
выбранную гонку с `raceAvailable=false`, пустыми строками и неизвестными временами.
Старый дисковый снимок квалификации отклоняется даже при запуске без сети.

`receivedAt` — время HTTP-получения, `changedAt` — когда наблюдалось изменение revision uid.
Повторное получение того же uid не подтверждает живые изменения. В завершённой сессии
тайминг не маркируется как текущая гонка. При сетевой ошибке отображается stale/unavailable.

Два независимых provider для auto/gt3 имеют собственные single-flight, историю и кэш.
Auto опрашивается сервером постоянно; закреплённая GT3 — по запросам браузера.
Последние нормализованные снимки сохраняются в `.cache/auto/snapshot.json` и
`.cache/gt3/snapshot.json` (Git-ignore). При смене session ID история очищается.
Auto сначала выбирает активную Type=0 сессию, предпочитая PresentationRoundId; затем
показанную завершённую гонку / ближайшую предстоящую / последнюю завершённую.
State завершённой гонки явно выводится в UI. Тренировки и квалификация исключены.
История сервера ограничена 30 кругами на машину и 100 событиями каждого вида.
Браузер хранит снимки до 135 с; TV Sync ограничен 120 с и не использует будущие снимки.
Настройки сохраняются в localStorage `gt3-preferences-v1`; все операции допускают недоступность storage.
CLASS фильтрует всю страницу через общий кэшированный classSnapshot, не меняя исходный снимок.
Таблица, 3D/2D-точки, PIT карты, Field, списки сравнения, времена, пит-стопы и смены пилотов
используют выбранный класс. Race Control сохраняет общие команды и сообщения хотя бы
об одной машине класса; CAR/CARS/#-ссылки распознаются отдельно от поворотов и секунд.
Сохранённый ручной выбор вне класса скрывается для текущего вида; All восстанавливает его.
Классы списка берутся из полного снимка; флаги, таймер и расписание остаются общими.
`raceMode` хранит auto/gt3. `comparisonScopes` хранит выбор отдельно по чемпионатам;
старый `comparison` сохраняется для совместимости настроек GT3. В GT3 по умолчанию A = №3,
B определяется по точной позиции P−1 из показанного (с учётом TV Sync/паузы) гоночного снимка.
В All режим использует точный P−1 общей классификации и не привязан к команде. При выборе
класса соперник — ближайший предшественник выбранного A внутри класса. Флажок
Auto: crew ahead of A доступен во всех сериях; включение сохраняет A, смена A сохраняет
авторежим, ручной выбор B отключает его. До выбора A флажок виден, но недоступен.
Если A вне класса, текущий вид очищается; All восстанавливает сохранённый выбор.
Если A лидирует,
не ранжирован или нужная строка отсутствует, B остаётся пустым. Списки ручного выбора видны
в самой панели сравнения. До старта они используют `entries.json`, после появления гонки
дополняются её фактическим составом. Наблюдаемый текущий пилот определяется только race-фидом.
Окно темпа 3/5/10 кругов общее для столбца PACE, избранного и сравнения.
В Lap comparison окно ограничивает последние реальные номера кругов объединённой истории A/B.
Круги совмещаются по номеру, не по индексу массива и не как последние круги разных номеров.
Каждая строка содержит LAP, A, B и Δ A−B в секундах; отсутствующая сторона остаётся прочерком.
Matched avg использует только пересечение одинаковых чистых кругов обеих машин в этом окне,
с явным числом пар; заголовок сообщает, кто быстрее и на сколько секунд на круг.
Race best — лучшее время всей гонки из источника. Полное LAST без наблюдаемой истории
может показываться в строке своего номера круга, но не считается подтверждённо чистым.
Пит/caution/неполное наблюдение обозначаются † и исключаются из среднего. Старые декоративные
столбики и две повторяющие одинаковые подписи колонки удалены; выбор A/B и авто P−1 сохранены.
Учитываются только валидные наблюдаемые зелёные круги без пит-лейна; замеченный внутри
круга caution также исключает его. Полоса S1/S2/S3 использует реальные времена и
прогресс SectBasedPcntPos; отдельные F1 mini-sector measurements недоступны.
Незавершённый LastLap не попадает в LAST. Когда наблюдается ровно один новый круг,
время может восстанавливаться из разницы TotalTime; пропуск нескольких кругов не делится на среднее.
Race Control сохраняет до 100 реально наблюдавшихся сообщений, несмотря на скользящее окно источника.
Пит/смены отображаются структурированными записями, сгруппированными только по номеру машины
и одинаковому времени наблюдения. Разные машины или моменты не склеиваются в один пит-стоп.
Пилот для отдельного PIT-события определяется только из предшествующей записанной смены;
если цепочка неполна/противоречива, имя не подставляется из текущего состава. Длительность
пит-стопа/стационарного обслуживания из времени опроса не вычисляется. Счётчик — число групп.
Неизменившиеся пит-события/Race Control не пересоздают DOM при каждом пакете тайминга;
выбор A/B обновляет выделение номера машины сразу. Форматтер MSK переиспользуется.
Браузер явно сортирует сообщения по убыванию времени; простое переворачивание массива не используется.
Времена этих сообщений обозначены WEST, прочие часы интерфейса — MSK.

## Запуск и проверка

`npm start` / `node server.mjs`; `npm run dev` — Node watch.
`npm run check` — синтаксис; `npm test` — содержательные проверки адаптера.
`start-dashboard.cmd` — локальный запуск с открытием браузера.

Переменные: `HOST` (по умолчанию `127.0.0.1`), `PORT` (3001).
Секреты и API-ключи не требуются. Порты соседнего F1-проекта не используются.

## Ограничения

Публикация в облаке не настроена. Внешние интеграции — Swiss Timing и географические тайлы OpenFreeMap.
GPS/радио/шины/погода трассы отсутствуют. Точки машин помечены Estimated: это оценка по
SectBasedPcntPos на калиброванном контуре, с документированной привязкой SRO/OSM.
MapLibre использует OpenFreeMap Positron, ту же приглушённую палитру, рампы толщины
дорожного контура и 3D-зданий, что соседний F1-проект. Global: pitch 48°, bearing −20°;
Top-down: 0°/0°. Выбор вида/режима/зданий/подписей/освещения сохраняется в prefs.map.
Поворот/наклон — правой кнопкой мыши, масштаб — кнопками или Ctrl+колесом; клавиатура
MapLibre поддерживает панорамирование/масштаб. ResizeObserver обновляет размер, Escape
закрывает настройки/разворот. При pagehide освобождаются map, worker, observer и listeners.
При ошибке WebGL/базового стиля доступен реальный локальный 2D-контур и Retry.
Следящие камеры требуют GPS и отключены. Расчётные точки отображаются в отдельном DOM-слое
над географической картой или SVG, с номерами A/B и №3; нажатие выбирает экипаж сравнения.
RAF работает на частоте браузера и освобождается при destroy. Позиции используют показанный снимок,
включая TV Sync, и setPlayback немедленно замораживает паузу. TimingPositions воспроизводит
завершённые сектора: TotalTime + sectorLapNumber + S1/S2/S3 задают общую гоночную шкалу
и реальные длительности отрезков. У завершённого круга начало = TotalTime − сумма секторов;
у текущего — TotalTime предыдущего круга. Неполные/невалидные сектора не достраиваются.
Буфер — 95-й процентиль длительностей трёх последних секторов каждой машины + 8 с доставки,
примерно сектор позади таблицы. Одиночный долгий пит и старые прогревочные сектора не
задерживают всё поле. При начале официальной гонки или избыточном буфере часы переустанавливаются.
Скорость внутри сектора постоянна: его реальная длина / измеренное время. До 12 отрезков
на машину хранят переходы секторов/кругов; новая revision не перезапускает движение.
При удлинении секторов буфер растёт плавно (воспроизведение временно 0,85×), без перемотки назад.
Задержка явно указана в статусе Sector replay. Исчезновение endpoints — buffering, без новых
вымышленных кругов. До наполнения буфера виден полученный source progress с подписью buffering;
отсутствие истории не скрывает машину. RED/source stale останавливают воспроизведение, reduced motion и завершённая
гонка показывают неподвижный source progress. Seek TV Sync сбрасывает будущие отсечки.
Порог отсутствия ревизий для карты равен буферу + 15 с (20–120 с), чтобы нормальный интервал
секторных пакетов длиннее 20 с не замораживал подтверждённое воспроизведение. Ошибка соединения
останавливает его сразу; выход за подтверждённые endpoints не допускается.
Поиск точки по длине контура — бинарный; проекция SVG/размеры кэшируются до изменения вида.
Стиль MapLibre обновляется только по изменению настроек/освещения/флага, не на каждом снимке.
Неизменившиеся transform/атрибуты точек не перезаписываются. Невидимый data-fps/data-draw-ms
слоя точек позволяет проверить частоту RAF и стоимость отрисовки без панели диагностики.
Неверный прогресс, PIT, DNF/DSQ/DNS не выводятся на круге. PIT имеет отдельную подпись.
Большие скачки и исправления прогресса не анимируются через полный круг.
Подтверждённые отсечки SRO, границы точности и план калибровки —
[docs/MAP_POSITION_RESEARCH.md](docs/MAP_POSITION_RESEARCH.md). Детали источников — [DATA_SOURCES.md](DATA_SOURCES.md).
